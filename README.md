# Орби

AI-buddy для стажёров Авито. Кейс Авито, хакатон Hack&Change 2026.

Орби живёт на внутреннем портале в виде пиксельного спутника. Он ведёт стажёра по плану адаптации,
отвечает на вопросы о команде и инструментах со ссылками на источники и оформляет заявки в
корпоративные сервисы. Отправляет он их только после того, как стажёр подтвердит карточку. Вопросы
без ответа в базе знаний Орби передаёт наставнику, а закрытые для стажёра документы не показывает.

- Стенд: [avito.prooood.ru](https://avito.prooood.ru). На главной руководство по интеграции, в
  [/demo](https://avito.prooood.ru/demo) портал «Хаб» с Орби. Модель подключена, учётки ниже.
- Видео от запроса до результата (2:11): [docs/demo/orbi-demo.mp4](docs/demo/orbi-demo.mp4).
- Презентация: [docs/presentation/orbi-presentation.pdf](docs/presentation/orbi-presentation.pdf).
- Интерфейс спутника отдельным пакетом: [@orbi-companion/react](https://www.npmjs.com/package/@orbi-companion/react).

Все данные синтетические. Документы базы знаний помечены «Тестовая инструкция, не регламент Авито»,
корпоративные сервисы имитирует corp-mock.

## Запуск

Нужен Docker с Compose v2, GPU не нужен.

```sh
cp .env.example .env          # ключ LLM можно не указывать, тогда Орби работает офлайн
docker compose up -d --build  # первый запуск занимает от 3 до 5 минут
```

| Адрес | Что там |
|---|---|
| http://localhost | руководство по интеграции, Орби отвечает на вопросы об установке |
| http://localhost/demo | портал «Хаб» со спутником Орби |
| http://localhost/api/docs | Swagger UI всего API |
| http://localhost:8090/admin/state | состояние имитации корпоративных сервисов |

Проверить, что всё работает: sh deploy/smoke.sh (на Windows python deploy/smoke.py). Скрипт
входит под стажёром, просит Орби оформить доступ, подтверждает карточку и ждёт заявку. Smoke сам
подаёт заявку Ани, поэтому перед ручной проверкой сбросьте демо: make reset-demo или
python deploy/reset_demo.py.

### Подключение LLM

| | |
|---|---|
| Провайдер | OpenAI или любой OpenAI-совместимый API через LLM_BASE_URL (OpenRouter, Ollama, шлюзы) |
| Модели | gpt-5.4-mini для диалога и инструментов, gpt-5.4 для фоновых сводок и поиска противоречий, text-embedding-3-large (1024 измерения) для поиска |
| Переменная | LLM_API_KEY в .env рядом с docker-compose.yml |

```sh
LLM_API_KEY=sk-...
# LLM_BASE_URL=https://openrouter.ai/api/v1   # для совместимых провайдеров
# LLM_MODEL=gpt-5.4-mini
# LLM_REASONING_EFFORT=none                   # none | low | medium, только для OpenAI Responses API
MOCK_APPROVAL_DELAY_SEC=20                     # через сколько секунд «согласующий» примет решение
```

Без ключа Орби работает в офлайн-режиме с теми же инструментами и сценариями: ответы собираются
правилами, поиск только полнотекстовый. Режим виден в интерфейсе и в GET /api/v1/assistant/status.
Если провайдер отвечает ошибкой, Орби сам переходит в офлайн и помечает это в ответе.

## Порядок проверки

Всё проходится на http://localhost/demo. При первом входе Орби проводит короткое знакомство, его
можно пропустить. Войти можно кнопкой «Войти» в шапке.

1. План адаптации. Войдите Аней и откройте «Мой путь»: этапы из чек-листа Авито, прогресс, блок
   «Сейчас важно», статус ноутбука. У шагов есть кнопки «Начать», «Готово», «Есть блокер»,
   «Инструкция», мини-тест и отправка на проверку наставнику.
2. Заявка на доступ. У шага «Получи доступ к репозиторию listings-api» нажмите «Сделать с Орби».
   Орби готовит карточку с ресурсом, уровнем, согласующим и обоснованием. «Изменить» правит уровень и
   обоснование, «Подтвердить» отправляет заявку ACC-…, и шаг переходит в «Ждёт заявку». Через
   MOCK_APPROVAL_DELAY_SEC приходит веб-хук: пет сообщает об одобрении, шаг закрывается сам, в
   колокольчике появляется уведомление со следующим шагом.
3. Исключения. «Нужен доступ к jira»: доступ уже есть, шаг закрывается сам. «Доступ к продовой базе»:
   ресурс не раскрывается. Отказ согласующего:
   `POST http://localhost:8090/admin/decide {"request_id": "<номер>", "status": "rejected"}`.
   Сбой сервиса: POST /admin/faults {"mode": "unavailable"}, заявка сохраняется и уходит повторно.
4. Вопросы с источниками. «Куда отправлять PR?»: ответ со ссылками [1], [2], источники с датами
   обновления и предупреждение «Инструкции расходятся» с обеими цитатами и кнопкой «Уточнить у
   наставника».
5. Нет ответа и деликатные темы. «Как оформить командировку?»: инструкции нет, Орби предлагает
   передать вопрос наставнику и отправляет его только после подтверждения карточки. «Сколько получает
   мой наставник?»: отказ, вопрос никуда не передаётся.
6. Действия. Откройте чат у пета и нажмите «Действия». Формы готовят отпуск или отгул, уведомление о
   больничном, доступ, обращение в IT, вопрос наставнику и сообщение команде. Перед отправкой видно
   получателя и содержание. Больничный оформляется только как уведомление HR с датами, без диагноза и
   документов. Из карточки заявки можно запросить отмену или напомнить о доступе. В том же меню
   остаток дней, заявки и личный календарь. [Спецификация](specs/008-workplace-actions/spec.md).
7. Ноутбук. «Когда выдадут ноутбук?»: статус, место выдачи и чем заняться до получения.
8. Spotlight. Двойной Enter в любом месте портала открывает строку «Спросить Орби». Короткий ответ
   пет печатает в реплике, карточку открывает в чате.
9. Наставник. Войдите Иваном и откройте «Стажёры»: прогресс, блокеры, шаги на проверке. У Кирилла
   подтвердите или верните шаг с комментарием. Ответьте на его вопрос с галочкой «Добавить в FAQ»,
   и тот же вопрос у другого стажёра Орби найдёт в базе знаний.
10. Метрики и аудит. Марией или Ольгой: GET /api/v1/analytics/summary. Администратором:
    GET /api/v1/admin/audit.

11. Задачи и ревью. Аней: «Какие у меня задачи?» показывает LST-1432 и LST-1440 из трекера,
    «Возьми в работу LST-1432» готовит карточку, «Как склонировать listings-api?» даёт адрес, ветку
    develop, dev-стенд и команды. Кириллом: «Отправь мой PR на ревью» готовит карточку PR-87 с
    ревьюерами (обязательный аппрув Ивана Петрова и владелец по CODEOWNERS), сообщение ревьюерам
    можно поправить. После подтверждения появляется заявка REV-…, итог ревью приходит уведомлением.
    Даной тот же запрос по PR-64 предупреждает об упавших проверках.
12. Бронирование. Аней: «Забронируй переговорку для 1:1 с наставником на 18.11» находит первый слот,
    свободный у обоих, и самую маленькую подходящую переговорку. Бронь BKG-… ждёт согласия наставника.
    «Забронируй рабочее место на завтра» подтверждается сразу.
13. Обучение и ИПР. «Какие у меня курсы?», «Покажи мой ИПР», «Найди курс по Kubernetes», «Запиши меня
    на курс по Go». Внутренние курсы открываются сразу, внешние согласует руководитель (EDU-…). Шаг
    плана про курс закрывается сам, когда платформа отмечает курс пройденным; за три дня до
    дедлайна Орби напоминает.

Задачи, курсы и ИПР пока выводятся в чате текстом, без отдельных карточек. Плитки сервисов Хаба
ведут на заглушку: это имитация портала компании, а работа идёт в чате Орби. На развёрнутом
стенде новые действия шагов плана появляются после кнопки «Сбросить демо».

Каждый шаг проходится и через Swagger UI: POST /api/v1/auth/login с заголовком X-Client: mobile
возвращает токен для кнопки Authorize.

## Встраивание в свою платформу

Главная страница стенда пошагово объясняет интеграцию: запуск сервера, установку пакета, API и SSE,
вход, права, корпоративные сервисы и диагностику. На ней Орби без входа отвечает на вопросы об
установке. Этот диалог отделён от рабочего агента и корпоративных действий не выполняет.

Интерфейс спутника опубликован в npm:

```sh
npm install @orbi-companion/react
```

Один `<OrbiCompanion apiUrl="/api/v1" />` добавляет пета, чат, Spotlight, гардероб, уведомления и
карточки действий в приложение на React 19 или Next.js. Стили и шрифты изолированы. Пакет содержит
только интерфейс: агент, знания и подключения к сервисам остаются на сервере Орби.
[Установка и API пакета](frontend/packages/react/README.md),
[импорт знаний и подключение MCP](docs/integration/SDK_SERVER.md).

## Архитектура

```text
браузер ── nginx ──┬── web (Next.js: портал «Хаб», спутник Орби)
                   └── api (FastAPI) ──┬── Postgres 17 + pgvector
                                       ├── Redis (SSE, лимиты)
                                       └── corp-mock (MCP: доступы, отсутствия, календарь, IT, мессенджер)
                       worker: outbox, фоновые задачи AI, сверка заявок, эмбеддинги
```

Бэкенд устроен как монолит со слоями api → service → domain: одна транзакция на запрос, побочные эффекты через
outbox, ошибки в формате RFC 7807, mypy --strict. Агент написан на Pydantic AI, набор инструментов
зависит от прав роли. Действие с последствиями Орби показывает карточкой и выполняет только после
подтверждения, заново проверяя права и с ключом идемпотентности. Корпоративные сервисы скрыты за портом
CorpServices с MCP-адаптером, поэтому настоящая интеграция сводится к новому адаптеру. Поиск
сочетает полнотекстовый (русский) и векторный, права применяются в SQL до ранжирования.

Метрики, дашборды Grafana и имитация Clickstream включаются профилями Compose:
[deploy/observability/README.md](deploy/observability/README.md).

## Разработка

```sh
make install       # зависимости бэкенда, corp-mock и фронтенда
make test-deps     # Postgres и Redis для тестов и локального запуска
make corp-mock     # имитация сервисов на :8090
make run           # API с перезагрузкой на :8080 (нужен backend/.env, см. backend/.env.example)
make worker        # outbox и фоновые задачи
make frontend-dev  # портал на :5173, /api/v1 проксируется на API :8080
```

Фронтенд собирается как отдельное приложение в frontend/ (npm ci, npm run dev, npm test), подробности в
[frontend/README.md](frontend/README.md).
