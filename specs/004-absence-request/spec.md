# Спецификация: отгул и отпуск

**Ветка**: `feat/ai-buddy-backend` · **Создано**: 14.11.2026 · **Статус**: реализуется

**Исходный запрос**: пример из самого кейса — стажёр хочет взять отгул. Орби объясняет порядок по
тестовой инструкции, проверяет остаток и пересечения с важными встречами, оформляет заявку после
подтверждения, показывает статус и помогает предупредить команду.

## Пользовательские истории

### История 1. Отгул без сюрпризов (P1)

**Независимая проверка**: «хочу взять отгул в пятницу» → Орби показывает остаток, пересечение с
1:1 наставника в пятницу, карточку заявки → подтверждение → заявка `ABS-…` `submitted` → веб-хук
`approved` → уведомление и предложение отправить сообщение в канал команды (отдельное подтверждение).

**Сценарии приёмки**
1. **Дано** стажёр запрашивает отгул на дату, **когда** Орби проверяет, **тогда** он вызывает
   `check_absence`: остаток дней (сервис отсутствий), правила тестовой инструкции, события календаря
   в эти даты с отметкой важности.
2. **Дано** пересечение с важной встречей (1:1, демо, экватор), **тогда** карточка содержит
   предупреждение и совет перенести встречу; заявку всё равно можно подать.
3. **Когда** стажёр подтверждает, **тогда** заявка уходит в сервис отсутствий
   (`absence.create_request`), сохраняется и показывается с номером; согласующий — руководитель.
4. **Когда** заявка одобрена, **тогда** Орби предлагает черновик сообщения в канал команды;
   отправка — только после второго подтверждения (`post_team_message`).

### Граничные случаи

1. Даты в прошлом или конец раньше начала → ошибка валидации без обращения к сервису.
2. Нарушен срок подачи (отгул < 2 рабочих дней, отпуск < 14 дней) → предупреждение «по инструкции
   подаётся за N дней, согласуй с руководителем»; заявка допускается.
3. Недостаточно дней → карточка не предлагается, Орби объясняет и предлагает отгул за свой счёт.
4. Отпуск в первые 3 месяца стажировки → предупреждение из тестовой инструкции.
5. Больничный → не заявка, а инструкция: сообщить руководителю и HR, оформить в сервисе (ссылка).
6. Сервис недоступен → как в 002: повтор воркером и уведомление.

## Подтверждение, отправка и ошибки

| Шаг | Что |
|---|---|
| Проверка | `check_absence(type, start, end)` — без побочных эффектов |
| Карточка | тип, даты, рабочие дни, остаток до/после, согласующий, предупреждения |
| Отправка | MCP `absence.create_request {employee_id, type, start_date, end_date, comment, idempotency_key}` |
| Результат | `{request_id: "ABS-…", status: "pending_approval"}` → `submitted` |
| Ошибки | валидация — 422 до карточки; сервис — повтор outbox; отказ — причина и совет |

## Требования

- **FR-001** Типы: `day_off`, `vacation`. Больничный — справка без заявки.
- **FR-002** Правила тестовой инструкции в домене (`domain/absence.py`): срок подачи, максимум подряд,
  ограничение для первых 3 месяцев; правила возвращают предупреждения, а не запреты, кроме дат и остатка.
- **FR-003** Даты в естественном языке («завтра», «в пятницу», «с 20 по 22 ноября») разбирает модель;
  в офлайн-режиме — доменный парсер дат.
- **FR-004** Сообщение в канал команды — отдельное действие с подтверждением (MCP `messenger.post_message`).

## Критерии успеха

- **SC-001** Заявка на отгул за ≤ 2 действия; 100% пересечений с важными встречами показываются до подтверждения.
