# Браузерные проверки полного стека

Тесты используют настоящий локальный Compose-стек через nginx, без подмены API.
Перед **каждым** тестом `deploy/reset_demo.py` сбрасывает демо в API и corp-mock,
включая счётчики заявок. Запускать на отдельном локальном стеке.

Из корня проекта (PowerShell):

```powershell
$env:LLM_MODE = "offline"
$env:LLM_API_KEY = ""
$env:MOCK_APPROVAL_DELAY_SEC = "15"
$env:SCHEDULER_INTERVAL_SEC = "1"
docker compose up -d --build --wait --wait-timeout 300
cd frontend
npm ci
npx playwright install --with-deps chromium
npm run e2e
```

На Linux задайте те же переменные через `export`. При другом локальном HTTP-порту
задайте `E2E_BASE_URL` (по умолчанию `http://localhost`). Если Python называется
`python3`, задайте `E2E_PYTHON=python3`. Docker должен быть доступен процессу тестов.
Задержка 15 секунд позволяет проверить промежуточное состояние «На согласовании».

Четыре сценария: доступ из плана → подтверждение → веб-хук → закрытый шаг,
уведомление и одобренная заявка; источники и противоречие в ответе про PR;
карточка вопроса наставнику про командировку; отправка сообщения на экране 375×812.
Используются роли, доступные имена и ожидания условий, без фиксированных пауз.

Тесты выполняются последовательно, без повторов, с новым браузерным контекстом
на каждый сценарий. Скриншот, trace и видео сохраняются при падении.
Отчёт: `npx playwright show-report`; артефакты `playwright-report/` и `test-results/`
уже исключены из Git. В CI также сохраняются логи и состояние Compose.

`npx playwright test --list` проверяет обнаружение сценариев без запуска Docker.
Vitest выбирает только `tests/**/*.test.{ts,tsx}`; E2E лежат отдельно и не входят
в unit-тесты и покрытие. Покрытие по всем `src/**/*.{ts,tsx}` сохраняется с порогом
100% строк.
