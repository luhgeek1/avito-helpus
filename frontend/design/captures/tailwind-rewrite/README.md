# Сравнение `main` и ветки `refactor/tailwind-rewrite`

## Как сравнивали

`compare.mjs` открывает одну и ту же страницу в двух prod-сборках (`main` на :5180, ветка на :5181) через Playwright и системный Chrome с фиксированным временем, локалью и `localStorage`. Анимации ставятся на паузу в начале. Для каждого элемента и псевдоэлемента (`::before`, `::after`, `::placeholder`, `::marker`) сравниваются все вычисленные CSS-свойства и прямоугольник с точностью 0,5 px. Затем через CDP принудительно включаются `:hover`, `:focus`, `:focus-visible` и `:active` у всех элементов, на которые есть такие правила, и сравнивается их поддерево. Переходы перед замером завершаются.

Охват: 20 сценариев (все маршруты портала, `/pets`, `/pets?pet=orbi-neo`, 404; главная и галерея — ещё и с туром знакомства) × 4 вьюпорта (1440, 1024, 800, 390 px), всего 80 страниц и 102 280 элементов. Состояния проверялись на 1440 и 390 px.

Запуск: `run-all.sh <префикс> <regexp маршрутов>` с переменной `B=<url ветки>`. Нужен `playwright-core` (например, во временной папке: `npm i playwright-core`). `analyze.mjs <отчёт.json> summary|detail` группирует расхождения по элементам.

## Результат

Реальных расхождений нет. `summary.txt` — итог анализатора. Оставшиеся строки объяснены ниже, остальное — эквиваленты:

| Нормализация | Почему это одно и то же |
| --- | --- |
| `transition-colors`, списки `transition-*` | Tailwind анимирует надмножество свойств (цвет рамки, outline, fill) с той же длительностью |
| `ease-out`, `ease-in-out`, `ease` | Кривые Tailwind вместо CSS-ключевых слов; отличие на 150–200 мс незаметно |
| `rgb()` / `oklab()` / `color(srgb)` | Одинаковый цвет в разной записи (`bg-black/44`, `bg-white/10`) |
| `box-shadow` | Tailwind добавляет прозрачные слои ring |
| `transform` ↔ `translate`/`rotate`/`scale` | Tailwind 4 использует отдельные свойства; геометрия совпадает |
| `background-position: 0 0` | Минификатор `main` писал `background: transparent` как `0 0` |
| `grid-template-areas` ↔ `col-*`/`row-*` | Мобильная шапка размещается номерами строк; геометрия совпадает |
| `start` ↔ `flex-start` | Синонимы |

Оставшиеся отличия:

- `sr-only` у подписи поиска событий: Tailwind скрывает через `clip-path` и `margin: -1px`; элемент так же невидим.
- Иконка «Главное из статьи»: цвет задаётся классом `text-purple`, а не атрибутом `stroke`; видимый штрих тот же.

## Баги `main`, исправленные после сравнения

В `main` при равной специфичности побеждал алфавитно более поздний сгенерированный селектор, поэтому часть модификаторов не работала. Сравнение выше выполнено, пока ветка воспроизводила это поведение. Затем по просьбе пользователя отдельным коммитом включено задуманное поведение — это единственные намеренные отличия от `main`:

1. Бейдж «Вы идёте» на странице событий серый: правило тега перебивало зелёное.
2. Большая кнопка лайка в статье не краснеет: цвет варианта `secondary` перебивал «liked».
3. Обложка статьи со скруглением 16 px вместо задуманных 24 px.
4. Вкладки на странице ИИ выглядят одинаково; у выбранной отличается только цвет текста при наведении.
5. У подзаголовка `/illustrations` нет отступа `mt-1`.
6. На телефоне колонка статьи шире экрана (`1fr` под картинку 480 px) — горизонтальная прокрутка.
7. Блок 404 без боковых отступов.
8. Пункты меню галереи на телефоне сохраняют нижний отступ 6 px.
9. У виджета пэта курсор `pointer` вместо `grab`; у кнопок гардероба `touch-action: manipulation` вместо `none`.
10. Ghost-кнопка («Прочитать все») с отступами размера, а не 0 4px.

Теперь: бейдж зелёный, большой лайк красный, обложка 24 px, активная вкладка ИИ белая, у подзаголовка отступ 4 px, статья на телефоне умещается в экран, у 404 обычные отступы колонки, пункты меню на телефоне без отступа, у пэта курсор `grab` (`grabbing` при перетаскивании), кнопки гардероба `touch-action: none`, у ghost-кнопки отступы 0 4 px.
