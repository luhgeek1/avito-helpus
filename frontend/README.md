# Frontend

Next.js 16.4, React 19, TypeScript и Tailwind CSS 4.3. Приложение следует Feature-Sliced Design; Next.js App Router отвечает за входные маршруты.

```text
app/
  layout.tsx                     Серверный layout, metadata и локальные шрифты
  page.tsx                       Главная /
  pets/page.tsx                  Галерея /pets и параметр ?pet=orbit
  globals.css                    Только подключение Tailwind и его конфига
src/
  _app/                          Клиентские провайдеры и композиция оболочки
  _pages/                        Страницы портала и галерея
  widgets/                       Оболочки портала и галереи, лента, коллекция, инспектор, спутник
  features/pet/                  Выбор, лайки, SVG, приветствие, пауза
  entities/pet/                  Данные, предпочтения, спрайты и UI петов
  shared/                        API портала, UI, навигация, конфигурация и фирменный знак
public/fonts/                    Локальные шрифты и OFL-лицензии
tailwind.config.ts               Тема, брейкпоинты и keyframes
postcss.config.mjs               Плагин Tailwind
next.config.ts                   Настройки Next.js
design/captures/                 Скриншоты и отчёты проверок
```

## Архитектура

- Направление импортов: `_app → _pages → widgets → features → entities → shared`. Префиксы `_app` и `_pages` исключают конфликт с зарезервированными каталогами Next.js.
- Каталог маршрутов `app/` импортирует публичные API FSD. Клиентская композиция находится в `src/_app`; страницы публикуются из `src/_pages/*/index.ts`.
- Слайсы одного слоя независимы. Между слайсами используй публичные API, например `@/entities/pet`, а внутри слайса — относительные импорты.
- Страница галереи — клиентская граница, её серверный маршрут передаёт разобранный searchParams. Metadata и локальные шрифты подключаются на сервере.
- Предпочтения читаются из localStorage после гидратации. До загрузки сохранённых лайков запись отключена, поэтому существующее избранное не затирается пустым массивом.
- Навигация использует Next Link и Next router. Layout сохраняет провайдер и спутника при переходах между страницами.

Steiger проверяет границы слоёв; только подсказка о префиксах `_app`/`_pages` отключена для этих каталогов. Существующие рекомендации об одном потребителе остаются предупреждениями.

## Орби и настоящий API

Декоративные разделы портала работают на моках MSW (`shared/api/portal`). Всё про стажёра идёт в
настоящий бэкенд `/api/v1`:

- `shared/api/orbi` — клиент: токен в памяти, refresh через httpOnly-cookie, ошибки RFC 7807
  (`OrbiError.code`), Zod-схемы, хуки TanStack Query, чтение SSE, поток `/events` (`useOrbiRealtime`).
- `features/orbi-chat` — стор диалога и UI сообщений: текст со ссылками на источники, противоречия,
  карточки подтверждения с правкой полей, заявки, план, техника, эскалации. `useOrbiChat().ask(текст)`
  открывает чат спутника с подготовленной фразой.
- `features/orbi-auth` — форма входа с демо-учётками.
- `_pages/orbi` — `/login`, `/plan`, `/requests`, `/questions`, `/mentor` (маршруты совпадают со
  ссылками в уведомлениях бэкенда).
- Спутник (`widgets/pet-companion`) использует тот же стор: чат, Spotlight (короткий ответ — в
  пиксельной реплике, карточка — в чате) и реплики на живые уведомления.

Для разработки подними бэкенд (`docker compose up -d api worker corp-mock db redis` в корне) и запусти
`npm run dev`: `/api/v1` проксируется на `ORBI_BACKEND_URL` (по умолчанию `http://localhost:8080`).
Сжатие Next выключено — иначе gzip буферизует SSE. Подробности протокола —
[../docs/frontend/API_INTEGRATION.md](../docs/frontend/API_INTEGRATION.md).

Тесты: `tests/orbi` (клиент, чат, экраны, realtime на записанных ответах настоящего API),
`tests/pets` (все 40 петов, галерея, спутник), `tests/portal`. Покрытие считается по всем файлам `src`.

## Стили

Используй Tailwind utility-классы прямо в TSX, включая адаптивность, состояния, псевдоэлементы и reduced motion. Не добавляй обычные CSS-файлы компонентов, CSS Modules или CSS-in-JS. `app/globals.css` — двухстрочная точка входа Tailwind, а тема и анимации задаются в `tailwind.config.ts`. Inline style допустим только для данных времени выполнения: положения спутника, палитры выбранного пета, масштаба и задержки кадров SVG.

Пиши стили на элементе, а не через дочерние селекторы вида `[&_button]` или `[&.is-active_.x]`: состояние передаётся условным классом через `cx` из `shared/lib/cx` (на базе tailwind-merge, поэтому позже переданный класс перекрывает ранний из той же группы) или вариантами `group-*`/`data-*`. Отступы и размеры бери из шкалы (`p-4.5` = 18 px), размеры шрифта — из `text-7`…`text-42`, радиусы — `rounded-lg`/`xl`/`2xl`/`3xl`; произвольные значения в скобках оставляй для разовых цветов и сложных значений. Медиазапросы портала — варианты `hub-max-1100/1000/900/720`. Маркер-классы (`widget-pet`, `pixel-pet`, `companion`, `collection-toolbar`, `pet-detail`, `pixel-dialogue`) нужны только JS-селекторам — не стилизуй через них.

`entities/pet/lib/sprite-frames.ts` кэширует четыре SVG-кадра по объекту Pet и объединяет пиксельные полосы одинакового цвета в один path. При изменениях рендера запускай `node frontend/design/captures/verify-sprite-paths.mjs` из корня: проверка попиксельно сравнивает все 160 кадров с прежним рендером через rect. Замеры гардероба — `profile-wardrobe.mjs`, полный сценарий — `verify-wardrobe-carousel.mjs`, непрерывность движения — `verify-wardrobe-motion.mjs` в том же каталоге.

Брейкпоинты сохраняют прежний дизайн: xs — 361 px, sm — 651 px, md — 851 px, lg — 1201 px, xl — 1600 px. Golos Text и Press Start 2P подключены через next/font/local. Лицензии рядом со шрифтами.

## Запуск и проверки

Из `frontend/`, нужен Node.js 20.9+:

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run check:architecture
npm run build
npm run start
```

Dev и production-сервер по умолчанию доступны на http://localhost:5173/. Для другого порта: `npm run dev -- --port 3000`. Production start выполняется после build. Артефакты Next.js находятся в `.next/` и игнорируются Git. Vite и старый React DOM entrypoint удалены. Корневого npm workspace нет.

Деплой на домашний сервер, Docker и автодеплой из GitHub Actions: [deploy/home/README.md](deploy/home/README.md). Для контейнера включён Next.js standalone; локальная команда `npm run start` сохраняется.

## Петы и состояние

Всего 40 персонажей, по четыре кадра. «Орби» — оригинал и 15 вариаций (16), «Раньше» — 25, «Все» — 40. Оригинал `orbit` находится в обеих тематических группах, без дублирования общего каталога. `/pets?pet=orbit` открывает его в предпросмотре, не меняя сохранённого спутника.

Оригинальный Орби рисуется в `entities/pet/lib/mascot-sprites.ts` на 32×32 с боковыми деталями, ножками и шарфом. Его четыре исходных кадра сохраняются. Вариации `orbi-*` рисуются отдельно на 64×64: `orbi-base.ts`, `orbi-sprites.ts`, `orbi-details.ts`, `orbi-detail-painter.ts`. Они парят без конечностей. Данные и палитры — в `entities/pet/config/`.

Избранное хранится в `buddy-favorites`, выбранный спутник — в `buddy-pet`, положение — в `buddy-position`. Спутника можно перетаскивать мышью/пальцем или двигать стрелками. Одиночный клик/тап раскрывает три пиксельных кружка по дуге: чат, гардероб и настройки. Двойной клик/тап открывает пиксельную реплику с печатью по буквам; у краёв окно меняет сторону. Кнопка «Показать сразу» завершает печать. При reduced motion или паузе весь текст виден сразу.

Два быстрых Enter/Return на странице или на пете открывают Spotlight, повторное двойное нажатие закрывает его (в том числе в поле запроса). Spotlight — одна белая строка с иконкой пета, как в последнем референсе пользователя. Введите запрос и нажмите Enter/Return или кнопку отправки, появляющуюся при вводе: демоответ появится в светлой пиксельной реплике рядом с петом с той же печатью текста, что при двойном клике; под Spotlight результатов нет, переписка сохранится в `buddy-chat`. Подсказка поля — «Спросить Орби». Окно можно независимо перетаскивать за любую часть, включая инпут; отдельной кнопки-захвата нет; его позиция хранится в `buddy-spotlight-position`. По краям курсор default, в поле — текстовый. Escape закрывает окно; у реплики пета свой крестик. Поля ввода и остальные кнопки сохраняют обычное поведение клавиатуры.

UI-проверки: `design/captures/verify-next-migration.mjs`, `verify-pixel-dialogue.mjs`, `verify-companion-drag.mjs`, `verify-orbit-menu.mjs`, `verify-wardrobe-carousel.mjs`. Используют Playwright из локальной установки design-studio; при другом окружении укажи установленный Playwright в import.

Общие требования — `../AGENTS.md`, дизайн — `../DESIGN.md`, статус и решения — `../docs/STATUS.md`, `../docs/DECISIONS.md`.

Гардероб спутника — локальная круговая карусель всех 40 персонажей с пятью видимыми миниатюрами и бесконечным зацикливанием. Колёсико, свайп и стрелки клавиатуры листают без изменения выбора. Клик выбирает пета через общий choosePet и сохраняет buddy-pet; избранное не меняется. Логика и UI находятся внутри widgets/pet-companion, каталог берётся из публичного entities/pet API.

Чат спутника: `ui/companion-chat.tsx`, `model/use-companion-chat.ts`, `model/chat-messages.ts`, `model/use-chat-placement.ts` внутри widgets/pet-companion. История и подготовленные ответы сохраняются в отдельном buddy-chat после загрузки сохранённых данных; при недоступном хранилище работает состояние в памяти. Чат открывается в фиксированной зоне справа, независимо от положения пета; его можно перетаскивать за шапку мышью, пальцем и стрелками клавиатуры. После закрытия чат возвращается в стартовую зону. Пет рисуется поверх окна при наложении. Окно с чёрной рамкой можно растягивать за верхний/левый края или верхний левый угол мышью, пальцем и стрелками клавиатуры; размер сохраняется отдельно в buddy-chat-size. UI-проверки из корня: `node frontend/design/captures/verify-companion-chat.mjs`, `node frontend/design/captures/verify-chat-resize.mjs` и `node frontend/design/captures/verify-chat-drag.mjs`.

Круговые меню: `use-radial-transition.ts` включает интерактивность по завершению CSS-перехода. Гардероб разделяет движение по дуге (внешний translate3d) и раскрытие (внутренний translate3d), фиксирует кадры миниатюр во время вылета CSS-правилом на контейнере и использует статические SVG-тени. Проверка раскрытия/перезапуска/листания во время появления: `frontend/design/captures/verify-radial-reveal.mjs` из корня; CDP-профилирование — `profile-radial-menus.mjs`.

## Портал «Хаб»

Страницы `landing` перенесены в `src/_pages/portal`, оболочка — в `widgets/portal-shell`, блоки ленты — в `widgets/portal-feed`. Маршруты App Router: `/`, `/profile`, `/people/[personId]`, `/events`, `/feed`, `/feed/[postId]`, `/benefits/[categoryId]`, `/services`, `/services/[serviceId]`, `/search`, `/ai`. `/pets` сохраняет прежнюю галерею. Существующий спутник находится вне CSS-области портала и сохраняет состояние при клиентской навигации.

`shared/api` публикует клиент, Zod-схемы и TanStack Query hooks. Моки MSW используют `getResponse` для fetch-запросов с префиксом API; Service Worker не нужен. `NEXT_PUBLIC_API_BASE_URL` по умолчанию `/api`; `NEXT_PUBLIC_API_MOCKS=false` отключает моки для отдельного backend. Пока backend не реализован. Настройки портала Zustand хранятся в `hub-preferences` отдельно от `buddy-*`.

`shared/lib/portal-navigation` адаптирует ссылки, параметры и фильтры к Next navigation. `shared/ui/portal` содержит общий UI портала и наборы классов: `buttonClass`, `chipClass`, `container`, `heading`, `paletteClass`, `focusRing`. Общие паттерны страниц (колонка, подзаголовок, липкая колонка) лежат в `_pages/portal/ui/classes.ts`. Inter 400/700 хранится с OFL-лицензией в `public/portal/fonts` и не заменяет шрифты пета.

`npm test` запускает 55 перенесённых тестов портала на Vitest/jsdom с mock Next navigation и MSW. Проверка интеграции в браузере: `node frontend/design/merge/verify-landing-merge.mjs` из корня, пока доступен `.git/codex-landing-merge/pet-manifest.json`. Проверка охватывает маршруты, фильтры, поиск, сохранение спутника при переходах, Spotlight, гардероб и галерею на 1440/390/320 px. Отчёт — `design/captures/landing-main-merge-verification.json`.

`design/merge/port-landing.mjs` сохранён как одноразовый инструмент переноса, а не команда обновления: он читает исходный checkout и перезаписывает файлы до ручных адаптаций Next.js. Повторно запускать его поверх приложения не следует.

## Первое знакомство

features/pet/onboarding хранит состояние первого визита (buddy-onboarding-v1=done), пропуск и повторный запуск. Провайдер расположен под PetPreferencesProvider; при отсутствии сохранённого персонажа выбирается defaultPet. Пока нет серверной авторизации, признак относится к браузеру.

Всё знакомство находится внутри widgets/pet-companion: model/use-companion-tour.ts управляет сценами, ui/companion-tour.tsx — нативным modal dialog, затемнением, компактным текстом и «Пропустить». Сам PetCompanion остаётся смонтированным, его прежние чат, меню, гардероб, Spotlight и настройки используются напрямую. Нет отдельного демочата, линейной примерочной или презентационной навигации. Сцены переключаются только кликом по свободной области или пробелом, последний переход завершает знакомство. Клики по настоящим кнопкам выполняют их функции. Пробел в полях ввода остаётся текстом; удержание клавиши не пропускает несколько сцен. При завершении пет уменьшается и перелетает в нижний правый угол. use-tour-exit.ts сохраняет нормальный размер и позицию без скачка при закрытии модального слоя.

Программа использует relocate без записи позиции; осознанное перетаскивание сохраняет buddy-position по прежним правилам. Перелёт между сценами анимирует только рисунок пета через Web Animations; меню раскрывается после перелёта. Исходная геометрия и CSS-переходы кругового меню/гардероба сохранены.

Чат и пиксельные реплики используют светлую палитру портала, меняются только цвета. Проверка: node frontend/design/captures/verify-onboarding.mjs из корня. Обычные сценарии пета устанавливают buddy-onboarding-v1=done. Исторический verify-landing-merge.mjs содержит хеши состояния перед merge; после последующих правок пета проверка тех хешей закономерно не актуальна.
