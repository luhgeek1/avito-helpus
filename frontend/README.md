# Frontend

React + TypeScript + Vite. Код организован по [Feature-Sliced Design](https://feature-sliced.design/docs/reference/layers).

```text
src/
  main.tsx                       Точка входа React
  app/
    app.tsx                      Композиция провайдеров, оболочки и страниц
    router/                      Маршруты и история браузера
    styles/                      Глобальные стили и токены
  pages/
    home/                        Главная-заглушка
    pet-gallery/                 Страница выбора пета
  widgets/
    workspace-shell/             Навигация и рабочая оболочка
    pet-collection/              Коллекция, фильтры и карточки
    pet-inspector/               Крупный просмотр и действия
    pet-companion/               Спутник в углу экрана
  features/
    pet/                         Группа независимых слайсов действий с петом
      choose/                    Выбор спутника
      favorite/                  Лайк и удаление из избранных
      download/                  Скачивание SVG
      greet/                     Демонстрационное приветствие
      toggle-animation/          Пауза и запуск анимации
  entities/
    pet/
      config/                    Каталог персонажей и палитры
      model/                     Типы, предпочтения, провайдер и хук
      lib/                       Рисование спрайтов и localStorage
      ui/                        PixelPet, PetCard и их стили
  shared/
    config/                      Публичная конфигурация маршрутов
    ui/                          Фирменный знак и общие визуальные примитивы
```

## Границы

- Импорты направлены вниз: `app → pages → widgets → features → entities → shared`. Допустимо пропускать слои.
- Слайсы одного слоя не импортируют друг друга. `features/pet` — группа слайсов, а не общий модуль с публичным API.
- Каждый слайс публикует нужные экспорты через `index.ts`. Между слайсами импортируй только публичный API, например `@/entities/pet` или `@/features/pet/choose`.
- Внутри слайса используй относительные импорты, чтобы не создавать циклы через собственный `index.ts`.
- `app` и `shared` разделены на сегменты, а не на бизнес-слайсы. Публичные точки входа общего UI — `@/shared/ui/avito-mark`, `@/shared/ui/primitives`; конфигурации — `@/shared/config`.
- Провайдер предпочтений пета собирается в `app`, а состояние и доступ к нему принадлежат сущности `pet`. Страницы и виджеты не обращаются к внутренним файлам сущности.
- Стили лежат рядом с владельцем в `ui/styles.css` и подключаются через публичный API. В `app/styles` остаются глобальные настройки, сброс и системный reduced motion.
- Нижние слои не импортируют роутер из `app`: оболочка и главная получают обработчики навигации через props.

Правила импортов и публичных API проверяет `npm run check:architecture`. Steiger также показывает предупреждения о самостоятельных слайсах с одним потребителем: это подсказка по размеру текущего прототипа, а не разрешение нарушать границы слоёв.

## Команды

Из каталога `frontend/`:

```sh
npm ci
npm run dev -- --port 5173
npm run check:architecture
npm run build
```

Сборка: `dist/` внутри `frontend/`. Локальный lockfile: `package-lock.json` рядом с `package.json`; зависимости — в `node_modules/` этого же каталога. Путь `@/` соответствует `src/` в Vite и TypeScript. Корневого npm workspace нет.

Для изменения образов используй `src/entities/pet/config/pets.ts` и `src/entities/pet/lib/mascot-sprites.ts` (новые маскоты), `src/entities/pet/lib/sprite.ts` (исходная серия и диспетчер отрисовки). Сохраняй чёткие пиксели, все четыре кадра, различимые силуэты и reduced motion. Общие инструкции и журнал — `../AGENTS.md` и `../CONTEXT.md`.

## Серии персонажей

`src/entities/pet/config/mascots.ts` содержит 15 новых концептов маскота Авито. `config/pets.ts` объединяет их с 10 исходными персонажами и новой серией Орби, сохраняя прежние ID и выбор в localStorage.

Новые спрайты рисуются в `lib/mascot-sprites.ts`, общие примитивы сетки — в `lib/pixel-painter.ts`. Каждый маскот имеет четыре различающихся кадра. При добавлении персонажей счётчики коллекции и навигации обновляются из массива данных.


## Семейство Орби

`config/orbi-family.ts` содержит 15 новых вариаций персонажа `orbit`, который понравился пользователю. Всего в каталоге 40 персонажей; фильтры «Орби», «Раньше», «Все» показывают 16, 25 и 40 вариантов: оригинальный Орби входит и в свою группу, и в предыдущую серию. «Избранные» показывает все отмеченные сердечком варианты независимо от серии.

`lib/orbi-sprites.ts` сохраняет общие черты семейства: один большой глаз, тёмный пиксельный контур, маленькие конечности и спутники. Варианты отличаются формой корпуса, верхними антеннами/частицами, отделкой, зрачком, направлением взгляда и цветами. Ноги, двигатели и боковые детали, похожие на руки, удалены по последнему уточнению пользователя.

`Pet` — дискриминируемое объединение: категория `orbi` требует `orbiDesign` со структурными параметрами. Порядок цветов в палитре этой серии: контур, корпус, основной акцент, дополнительный акцент, необязательный пятый цвет спутника. Оттенки бликов вычисляются без сглаживания. Данные, модель и рисование остаются внутри FSD-слайса `entities/pet`.

## Избранные

`features/pet/favorite` — действие лайка. Оно используется в коллекции и инспекторе. `entities/pet` хранит favoriteIds в общем провайдере предпочтений и восстанавливает их из `buddy-favorites` в localStorage. Повреждённый JSON, дубли и неизвестные ID отбрасываются; при недоступном хранилище избранные работают до закрытия текущей сессии. Выбор спутника остаётся в отдельном ключе `buddy-pet`.

`PetCard` принимает слот `actions`: сущность не импортирует фичу лайка. Карточка — article с отдельной кнопкой предпросмотра, лайк — соседняя кнопка. Вложенных кнопок и побочного открытия предпросмотра при лайке нет. Вкладка «Избранные» имеет счётчик, удаление без перезагрузки и пустое состояние. На узких экранах фильтры размещаются в две строки.

Оригинальный Орби (`orbit`) — `defaultPet` из публичного API сущности Pet. Он первый во вкладке «Орби» и используется для предпросмотра при отсутствии сохранённого выбора. Параметр `?pet=orbit` открывает оригинал явно; он меняет предпросмотр, но не записывает выбранного спутника и не меняет избранные.


## Детальная отрисовка вариантов Орби

У категории `orbi` есть обязательный `orbiDesign.finish`: 15 вариантов отделки от неоновых и стеклянных до керамических и ботанических. `orbi-base.ts` задаёт базовую форму 32×32; `orbi-sprites.ts` строит изображение 64×64; `orbi-details.ts` содержит отделку и формы частиц, `orbi-detail-painter.ts` — целочисленные примитивы. Корпус и внешние частицы рисуются раздельно, детали ограничены маской, чтобы не появлялись конечности или выступы.

PixelPet, pixelRuns и SVG-экспорт автоматически учитывают размер сетки. Оригинал и остальные прежние персонажи остаются 32×32; масштаб и SVG оригинала не изменились.

Последняя правка оригинала — самая первая версия `orbit` с боковыми деталями, ножками и шарфом. Она изолирована в `mascot-sprites.ts` и полностью совпадает с четырьмя исходными кадрами. Исключение касается только оригинала; `orbi-*` по-прежнему парят без конечностей.

## Материалы петов

Весь фронтенд и его вспомогательные файлы находятся внутри этой папки. Данные и отрисовка петов — `src/entities/pet/`; изображения, анимации, скриншоты и отчёты — `design/captures/`; журнал дизайнерских решений — `design/decisions.md`. Папка `design/` перенесена из корня без изменения файлов изображений.

Запуск из корня репозитория без перехода в каталог: `npm --prefix frontend run dev -- --port 5173`. Установка: `npm --prefix frontend ci`. Основной вариант — перейти в `frontend/` и выполнять команды здесь.
