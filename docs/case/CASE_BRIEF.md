## Что нужно сделать

Прототип AI-buddy для стажёров: 3–5 сценариев или один глубокий. Обязательные шаги:

1. CJM первых недель по чек-листу и выбранные сценарии.
2. Ответы о команде и инструментах с учётом контекста.
3. Все выбранные сценарии, хотя бы одно действие через корпоративный сервис или его имитацию.
   Действие выполнено, когда сервис вернул результат, а помощник **показал и сохранил** его.
4. Этапы адаптации, статусы задач, следующие шаги.
5. Обоснование архитектуры, прав доступа и интеграций.
6. Метрики пользы и способ проверить эффект (A/B).

Состав сдачи: работающий прототип; код и README (Docker, версии зависимостей, тестовые учётки,
порядок проверки, запуск тестов); SDD-спецификации; тесты и отчёт о покрытии **>80% строк**;
тестовые данные и моки интеграций; видео «от запроса до результата»; презентация PDF; описание внешних
API (сервис, модель, переменная окружения, пример конфигурации без секретов).

Ограничения: стажёры — основная аудитория; только синтетические данные, тестовые инструкции нельзя
выдавать за регламенты Авито; не клон HR-системы; права учитываются (скрытое не утекает, запрещённое
не выполняется); нет чувствительных ПД и финансовых операций; локальные операции UI < 1 с, вызовы LLM
неблокирующие, со статусом ожидания и обработкой отказа.

## Уточнения организаторов

**Стек и LLM**
- Go не обязателен, подойдёт любой язык (№52–53, чат 11.11). Оценивают совместимость архитектуры
  со стеком Авито: Go/Python, PostgreSQL, Redis, React/TS/TanStack/Zustand/Zod, Docker, Grafana,
  RPC/Kafka, CI/CD.
- Достаточно веб-чата.
- Ключи для разработки не выдают. Для проверки жюри подставит свой ключ под провайдера из README
  («укажите сервис, модель, переменную окружения и пример конфигурации»). Любой провайдер или
  локальная модель; OpenAI-совместимые API (OpenRouter, GigaChat) допустимы (№54), Avito A-Vibe тоже (№47).
- Тестовый режим без ключа допустим, если явно обозначен и в README описано подключение реальной
  LLM (№55, чат 12.11). GPU не будет, запуск через Docker (№45).
- У других команд падали бесплатные облачные эмбеддинг-API: на такие зависимости не полагаться.

**Покрытие и SDD**
- Покрытие >80% считается по всему прикладному коду команды, **включая веб-интерфейс**, общим
  процентом (№70–73, чат 12.11). Моки корпоративных сервисов исключаются. Форматы LCOV, Cobertura, Istanbul.
- SDD: предпочтительно SpecKit, OpenSpec допустим (№68). В спецификации показать, когда запрашивается
  подтверждение, что отправляется в сервис и как обрабатываются результат и ошибки (№67).

**Что считается сильным решением**
- «LLM поверх чек-листа» недостаточно: нужны конкретные действия от потребности до результата (№8).
- Глубокий сценарий = реальные шаги и исключения. Пример: выдача ноутбука — сроки, место,
  уведомления, чем заняться до получения (№12). CJM помогает.
- Типичные вопросы: «Как скачать репозиторий?», «Куда отправить PR?», «Кого позвать на ревью?»,
  «Как проверить фичу на dev?», «Где задачи и ИПР?», «Как получить доступ?», «Когда выдадут ноутбук?» (№5).
- Частые ошибки стажёров: непроверенный код от LLM, кодстайл и архитектура, запуск микросервисов,
  инфраструктура (№7).
- Права: RBAC/ABAC (№17, №23, №42). Подтверждение для действий, влияющих на сотрудника, доступы и
  процессы (№22).
- Противоречие общей и командной инструкции: показать оба варианта и передать наставнику (№26, №38).
- Нет ответа: эскалация наставник → руководитель → HRBP (№27).
- Встраивание в существующую платформу — более простой путь к внедрению (№43).
- Корпоративные сервисы можно имитировать: REST, OpenAPI, MCP, JSON, тестовая БД (№62). Нужна
  правдоподобная имитация с понятным путём к реальной интеграции (№82). Красивый макет без логики
  критерии не закрывает (№81).
- Обзор прогресса для наставника или руководителя полезен (№85).
- Метрики и A/B ожидаются, технические метрики (P99, Web Vitals) тоже (№75–77).
- Можно использовать палитру Авито, брендбука нет (ориентир — Авито Старт).

**Процессы Авито (для правдоподобия)**
- Заявки на доступ: внутренний сервис или Jira. Поля: проект/ресурс, обоснование, уровень
  (чтение, редактирование, администрирование). Согласует владелец ресурса, руководитель или DevOps;
  стажёр может сначала уточнить у наставника. Процесс заявки моделируем сами: создать, показать
  статус, получить результат согласования.
- Стажёры получают те же доступы, что и команда: Jira, Confluence, Redash, Grafana, Stash.
- В Авито уже есть: сервисы отсутствий, командировок, найма, увольнений, согласий, бенефитов,
  чек-лист новичка; настройка AI-агентов с промптами и MCP, внутренний AI-крон, feature flags. Их можно
  имитировать и оформлять действия через MCP.
- Инструменты команд: Mattermost, Jira, Confluence, Bitbucket (Stash), Grafana, Redash, Docker, K8s (№58).

**Базовые метрики (для гипотез и A/B)**
- До первой самостоятельной задачи ≈ 2 недели; адаптация ≈ 2 месяца.
- Удовлетворённость: онбординг 9/10, чек-лист **68%**, наставник 90%.
- Наставник тратит ≈ 5 ч/нед в первые 2–3 месяца, затем 2–3 ч; за программу 40–48 ч (6 мес.) или 55–65 ч (9 мес.).
- Типы вопросов: организационные (доступы, техника, документы), задачи, профессиональные и
  инструменты, развитие (ИПР, матрица компетенций), обратная связь.
- Цели «быстрее к самостоятельной работе» и «меньше повторных объяснений» равноценны.
