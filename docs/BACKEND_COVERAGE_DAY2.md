## Дополнительные проверки поведения

- Неизвестные и чужие записи скрываются; карточки повторно проверяют права; решение по одной
  карточке закрывает соседние. Закрытый шаг не открывается привязкой новой заявки; коллизия
  внешнего номера завершает обе неоднозначные открытые заявки.
- SSE проверяет авторизацию перед выдачей уже полученного события, не выдаёт его после отзыва
  авторизации, отправляет keepalive и освобождает подписку при завершении.
- Ошибки API имеют RFC 7807; очищение cookie при неверном refresh, CSRF, баны, истёкшие и
  отозванные сессии проверены отдельно. Время в ответах агента и сериализации проверяет также
  сохранённый набор `test_polish*`.
- Проверены отказы и таймауты MCP, деградация Redis, сбои генерации и эмбеддингов,
  недоступность корпоративных сервисов, повторная доставка outbox и ограничения cron.
- `test_untrusted_knowledge.py` использует намеренно враждебную локальную модель: после чтения
  команды из тестового документа она пытается создать доступ. Инструмент выдаёт только карточку;
  до подтверждения и после её отклонения заявки и внешнего вызова нет. Это проверка серверной
  границы подтверждения, а не утверждение об устойчивости внешней LLM ко всем инъекциям.

## Качество поиска

Исходный `KnowledgeService` из `HEAD` и текущий сервис сравнены на одной и той же заполненной
тестовой БД, с одинаковыми UUID разделов и без эмбеддингов. Результаты до/после совпали:

| Набор | Recall@5 до → после | MRR@5 до → после | Нужный раздел в top-5 до → после |
| --- | --- | --- | --- |
| Исходный, 29 вопросов | 0,965517 → 0,965517 | 0,820115 → 0,820115 | Не измеряется этим набором |
| Расширенный, 10 вопросов | 1,000 → 1,000 | 1,000 → 1,000 | 1,000 → 1,000 |

В исходном наборе остаётся прежний промах «Когда релизы у команды?». Расширенный eval теперь
защищает все три ранее достигнутых значения 1,000. Проверка скрытых документов также сохранена.
Полное совпадение сравнения записано в артефактах; порядок равных результатов может зависеть от
UUID нового сида, поэтому сравнение выполнялось на одном корпусе.

## Предложения для D-xxx

Номера назначает владелец `DECISIONS.md`; сам файл не изменён по ограничению задания.

1. **Деградация поиска сохраняет транзакцию.** Ошибки необязательного векторного запроса
   изолируются savepoint. Отвергнуто: ловить исключение без отката повреждённой транзакции.
2. **Противоречия учитываются по паре разделов.** Известная пара не подавляет проверки других
   команд. Инструкции из текстов правил отдельно объявлены недоверенными данными.
   Отвергнуто: проверять только первую команду и считать всю тему обработанной.
3. **Приватные темы фильтруются в инструменте.** Отказ действует и до карточки, и при
   подтверждённом исполнении; переход из результатов поиска не обходит его.
   Отвергнуто: полагаться только на промпт или офлайн-маршрутизатор.
4. **Mock соблюдает идентичность операции.** Повтор сообщения сохраняет автора, канал и текст;
   специализированный инструмент принимает только свой вид заявки.
   Отвергнуто: возвращать чужой результат по совпавшему ключу или номеру.
5. **Уведомление предлагает только поддержанное действие.** Напоминание согласующему доступно
   для access; для absence/equipment даётся следующий шаг через человека.
   Отвергнуто: единая кнопка напоминания с последующим 409.
