# Сервер для npm-виджета

React-библиотека переносит весь интерфейс спутника. За ответы, историю, знания, права, MCP,
подтверждения, outbox и уведомления отвечает сервер Орби. Контракт —
[OpenAPI](../api/openapi.json) и [SSE](../frontend/API_INTEGRATION.md).

## Запуск

`docker compose up -d --build` в свежем клоне после `cp .env.example .env`.
Существующий `.env` не перезаписывайте. Подключите `/api/v1` к домену платформы через прокси
без буферизации SSE; ключи модели остаются в `.env` сервера. Портал при этом не обязателен для
npm-виджета: форму входа и интерфейс чата он содержит сам.

Без ключа LLM работает детерминированный офлайн-режим; с `LLM_API_KEY` — модель из `LLM_MODEL`.
`LLM_BASE_URL` позволяет указать OpenAI-совместимый шлюз. Состав контейнеров и переменные —
[корневой README](../../README.md).

## Добавление контекста

Контекст пользователя сервер строит из своей БД: человек, роль, команда, наставник, день стажировки
и ближайшие задачи. Клиентский `sessionKey` только сбрасывает приватное состояние интерфейса;
он не задаёт личность и не даёт прав. SSO интегрируется на сервере, с проверкой токена и связью
с записью сотрудника. Готового произвольного OIDC-коннектора в этой версии нет.

Документы загружаются оператором из Markdown с YAML front matter.
Образец: [knowledge-example/sdk-installation.md](knowledge-example/sdk-installation.md).
Обязательны `slug`, `title`, `scope`, непустой список `roles`, `owner`, `updated_at`.
Для `scope: team` обязателен UUID существующей команды в `team_id`; для `company` он запрещён.
`kind`: policy / guide / tool / faq / glossary. `source_url` — необязательный HTTP(S)-источник.
Все примеры и импортированные инструкции на этом стенде помечаются тестовыми.

```sh
# Из backend, сначала без подключения к БД:
uv run python -m app.cli knowledge-import ../docs/integration/knowledge-example --check
# Загрузить с DATABASE_URL из окружения или backend/.env:
uv run python -m app.cli knowledge-import ../docs/integration/knowledge-example
# Осознанно обновить существующие slug:
uv run python -m app.cli knowledge-import ../docs/integration/knowledge-example --replace
```

В Docker: `docker compose cp docs/integration/knowledge-example api:/tmp/orbi-knowledge`, затем
`docker compose exec api python -m app.cli knowledge-import /tmp/orbi-knowledge --check` и та же
команда без `--check`. Повторная загрузка существующего документа требует `--replace`.

Один пакет — одна транзакция: неверная команда или коллизия slug откатывает всю загрузку.
Ограничения: 1–100 файлов `.md`, до 1 МБ на файл, без symlink. Разделы индексируются сразу для
полнотекстового поиска; эмбеддинги — через outbox/воркер, если включены. Права применяются до поиска.
Загрузка не стирает пользователей, заявки, планы и другие документы.

## MCP

`CORP_MCP_URL=http://corp-mock:8090/mcp` уже подключён к серверу и воркеру в Compose.
Чтобы заменить имитацию совместимым сервисом, настройте URL на **сервере**. Его методы и ответы
должны соответствовать `backend/app/infra/corp_mcp.py` и порту `backend/app/service/ports.py`:
проверка и создание доступа, отсутствия, календарь, техника, IT, справочник и мессенджер.

Для Jira/Confluence или MCP с другим набором инструментов реализуйте адаптер `CorpServices`.
Одного произвольного URL недостаточно: необходимо сопоставить операции, права, поля и результаты.
Сохраняйте подтверждение карточки, идемпотентный ключ, outbox, проверку прав при исполнении и
подпись веб-хуков (`CORP_WEBHOOK_SECRET`). Ключи MCP и LLM не передаются браузеру.

## Что потребуется для другой компании

- Развернуть сервер и воркер с Postgres/Redis; настроить модель и домен API.
- Подключить проверку SSO и оргструктуру вместо синтетических учёток.
- Загрузить разрешённые документы и адаптировать корпоративные сервисы по контракту выше.
- Установить npm-пакет, передать API и авторизацию, сопоставить ссылки с маршрутизацией платформы.

Пакет не является самостоятельной универсальной системой управления агентами: он предоставляет
готовый интерфейс и проверенное подключение к текущему серверному контракту Орби.
