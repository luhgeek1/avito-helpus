## Готово

- **Бэкенд** (`backend/`): FastAPI-монолит.
  План адаптации из чек-листа Авито, заявки на доступ, отгул и IT с подтверждением, гибридный поиск с
  ACL и противоречиями, эскалации наставник → руководитель → HRBP с FAQ, экран наставника,
  уведомления и SSE, аналитика, флаги, аудит. 50 эндпоинтов, OpenAPI — `docs/api/openapi.json`.
- **Агент Орби** на Pydantic AI: `gpt-5.4-mini` (Responses API), карточки подтверждения, офлайн-режим
  и автоматический фоллбэк. Предыдущий этап зафиксировал на живой модели первый токен ≈ 1–2,5 с;
  на этом этапе внешняя модель не вызывалась.
- **corp-mock** — MCP-имитация сервисов доступов, отсутствий, календаря, IT и мессенджера.
  Короткие номера `ACC-1042` / `ABS-2101` / `IT-3301`, отдельный сохраняемый счётчик,
  проверка ключей, идемпотентные решения/напоминания и отмена. Обычный reset сохраняет счётчики;
  согласованный сброс после очистки API возвращает демо-начало. Старые длинные номера читаются.
- **Наблюдаемость и Clickstream**: опциональные Compose-профили Prometheus/Grafana и Kafka KRaft,
  метрики API/воркера, два дашборда, правила алертов, read-only SQL-представления и роль Grafana.
  Синтетические события уходят через атомарный outbox, HMAC-envelope и aiokafka; повторы/дедупликация,
  сбой брокера не задерживает бизнес-операции. Инструкция — `deploy/observability/README.md`.
- **Переносимость и запуск для жюри**: tzdata, LF, исключение локальных .venv из образов,
  Windows-сигналы worker и проверка ключей, строгий smoke на Python, команды PowerShell без make.
  Smoke проходит на пересобранном с нуля Docker-стеке (Windows 11), см. BACKEND_REVIEW.
  Согласованный сброс — `python deploy/reset_demo.py` с остановкой API/worker на время сброса.
- **Корректность и права**: коллизии номеров не ретраятся как сеть; отмены/напоминания через outbox;
  исправлены гонки создания и привязки плана, сбой dead-handler, ACL деликатных вопросов/конфликтов,
  ошибки веб-хука, время Москвы, срок авторизации SSE. Отчёт — [BACKEND_REVIEW.md](BACKEND_REVIEW.md).
- **Знания**: инструкции по CI и БД, кодстайл, проверка LLM-кода, доступы, пересказ публичного Playbook.
  Новые 10 вопросов: recall@5 30% → 100%, MRR@5 0,25 → 1,00, раздел в top-5 10% → 100%.
  Старый eval и ACL проходят; код поиска не менялся. Командировки оставлены для эскалации.
- **Качество**: настоящий Postgres/Redis — бэкенд **293 passed, 1 deselected** (95,9%), фронтенд
  **117 passed** (93,9% по всем файлам `src`), общее покрытие строк **95,2%** (`make coverage`). tsc и steiger чистые.
  Ruff и mypy --strict чистые; миграции вниз/вверх и модели проверены. Оба uv.lock проходят offline check.
  Новые регрессии проверяют счётчики после reset/рестарта/потери снимка и первую заявку Ани `ACC-1042`.
- **Нагрузка**: стандартный Python-скрипт `deploy/loadtest.py`, 20 пользователей / 60 с на прямом
  локальном API: 15 711 запросов, ошибок 0, 2502 ожидаемых 429 чата. У простых операций p95 88–140 мс,
  max 368 мс. Без nginx/внешней LLM; исходный эталон команды сохранён отдельно в README.
- **Документы**: README с порядком проверки через интерфейс, ARCHITECTURE, DECISIONS D-001…D-024,
  OpenAPI, SpecKit и CJM, гайд API для фронтенда.
- **Фронтенд подключён к API** (D-023): вход с демо-учётками, «Мой путь», «Заявки и вопросы»,
  «Стажёры» (экран наставника), живые уведомления в шапке. Чат спутника и Spotlight работают с настоящим
  агентом: источники, противоречия, карточки с правкой полей, заявки, офлайн-бейдж; пет озвучивает
  уведомления. Поток `/events` по `auth.required` (D-020) обновляет токен, переподключается и
  перечитывает данные. Флагман пройден в браузере на живой модели: «Сделать с Орби» → карточка →
  правка уровня → подтверждение → веб-хук → шаг закрыт. Декоративные разделы портала остаются на моках.
  Стили — только Tailwind (D-013), inline-стили лишь для значений времени выполнения.
- **Деплой**: предыдущий этап зафиксировал стек на `avito.prooood.ru` и автодеплой из `main`,
  см. [deploy/home/README.md](../deploy/home/README.md) и D-012. Live-деплой этим этапом не проверялся.
