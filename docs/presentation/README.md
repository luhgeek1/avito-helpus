# Презентация «Орби»

Готовый файл: [orbi-presentation.pdf](orbi-presentation.pdf). 18 страниц 16:9: 12 основных слайдов,
разделитель «Приложения» и A1–A5. Первый слайд — порядок проверки и ссылки на код, интерфейс и видео.

Редактируемая копия для PowerPoint и Google Slides: [orbi-presentation.pptx](orbi-presentation.pptx) —
те же слайды, тексты и таблицы правятся, картинки только у скриншотов и Орби. Сдается PDF; если
правили PPTX, экспортируйте его в PDF заново.

## Пересборка

Из корня репозитория:

```powershell
node docs/presentation/build.mjs
```

Нужны Node.js и Playwright с Chromium из `frontend/node_modules`. Для нового окружения:

```powershell
npm --prefix frontend ci
npm --prefix frontend exec -- playwright install chromium
```

Сборщик проверяет вылет текста за границы блоков, загрузку шрифтов и картинок, отсутствие сетевых
запросов. Затем пишет PDF рядом с собой и PNG-превью в `preview/` (каталог не коммитится; другой путь —
первым аргументом или `ORBI_PREVIEW_DIR`).

| Файл | Назначение |
|---|---|
| `slides.html` | Слайды 1920×1080: стили, схема, тексты |
| `build.mjs` | Проверки макета и сборка PDF и превью |
| `build_pptx.py` | Сборка PPTX из того же `slides.html` (python-pptx, Pillow, Playwright): `python docs/presentation/build_pptx.py` |
| `assets/` | Скриншоты прототипа и кадр оригинального Орби |

Шрифты — Golos Text и Press Start 2P из `frontend/public/fonts/` (WOFF2), внешних ресурсов нет.

## Заголовки по порядку

1. Орби — AI-напарник стажера Авито (порядок проверки, код, интерфейс, видео).
2. До самостоятельной задачи — ≈ 2 недели; наставник тратит ≈ 5 часов в неделю.
3. Орби доводит до результата: план, ответы с источниками и заявки.
4. Доступ — действие и подтверждение; после одобрения шаг закрывается сам.
5. Орби уточняет, когда не знает, и отказывает, когда действие запрещено.
6. Ответы опираются на источники; расхождения инструкций видны стажеру.
7. Ответ наставника пополняет FAQ — следующий стажер получает его от Орби.
8. Модель предлагает карточку — бэкенд проверяет права и исполняет через MCP.
9. Сравнение альтернатив определило стек, поиск и исполнение действий.
10. 661 автотест и 4 E2E проверяют сценарии; покрытие прикладного кода — 100%.
11. Эффект проверим запуском по командам — цели пока остаются гипотезами.
12. Орби встраивается одним React-компонентом, а сервисы Авито подключаются адаптерами.
13. Приложения.
14. A1. Орби помогает с отгулом и техникой, проверяет шаги и напоминает о сроках.
15. A2. Действие требует подтверждения, а права проверяются сервером повторно.
16. A3. Мониторинг и экспорт событий подключаются профилями к запуску одной командой.
17. A4. Каждая метрика пилота считается из событий Орби и статусов заявок.
18. A5. Монолит API и воркер: PostgreSQL для данных, Redis для pub/sub, сервисы — через MCP.

## Объем текста и проверка

Основные слайды 2–12 содержат до 60 слов каждый. `node docs/presentation/build.mjs` считает текст
внутри `.body` и сохраняет `bodyWords` в `preview/build-report.json`. Слово — разделенный пробелами
токен с буквой или цифрой: числа, номера шагов и технические обозначения учитываются;
отдельные знаки и стрелки — нет. Заголовок, подпись к скриншоту, сноска и колонтитул исключены.

## Содержание и визуальная проверка

- 2: два вопроса с иконками связывают исходные метрики с обращениями к наставнику.
- 6: три тезиса набраны 28px и дополнены иконками; скриншот не заходит в колонтитул.
- 7: увеличен фрагмент «Вопросы стажеров», поле ответа и согласие на FAQ; справа общая сетка.
- 8: инфраструктура заменена последовательностью одного действия на четырех дорожках.
  Видны карточка `ApprovalRequired`, согласие, повторная проверка RBAC/ABAC, outbox,
  MCP, подписанное одобрение и уведомление. Пунктир отделяет модель, три гарантии сохранены.
  Это исправляет несоответствие прежней иллюстрации заголовку.
- 12: ограничения набраны 24px, заголовки пунктов — цветом `--ink`; высота колонок совпадает.
- Разделитель: добавлен A5. В A5 сохранены компоненты прежней схемы, сгруппированы в три колонки.
  Общие зависимости API и worker проведены от рамки монолита; SSE — от API, веб-хук — к монолиту.
  PostgreSQL хранит данные и outbox, Redis обслуживает pub/sub и лимиты.
- 1, 3–5, 9–11, A1–A4: сохранены заголовки и содержание; на 3 немного увеличена высота кадра плана.
  На всех основных слайдах тело начинается на 310px, подписи — от 18px, серый текст — `--muted`.

PDF и все 18 PNG-превью проверены визуально; 2, 6, 7, 8, 12 и A5 дополнительно проверены
крупными фрагментами. Сборщик проверяет границы, локальные шрифты и ресурсы, отсутствие внешних
запросов, кегль от 18px, объем тела и отсутствие буквы с двумя точками в авторском тексте.
Исходные продуктовые PNG не изменены.

Сборка PPTX проверяет весь редактируемый текст против HTML, две нативные таблицы, ссылки
и соответствие заголовков README. Новые диаграммы используют прямые ортогональные SVG-пути,
которые экспортируются нативными линиями; пунктир границы доверия сохранен.
Отрисовка PPTX в PowerPoint / LibreOffice не проверена: LibreOffice в окружении отсутствует.
